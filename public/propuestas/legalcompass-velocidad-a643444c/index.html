Lo que encontramos

La web no guarda copias de sus páginas El más grave

El servidor arma cada página desde cero en cada visita y eso toma unos 2 segundos. El hosting trae un sistema de caché (LiteSpeed) pensado justo para esto, pero está instalado y apagado.

Seis paquetes de complementos haciendo lo mismo Grave

La web usa seis paquetes de complementos para Elementor: Essential Addons, Happy Addons, Ultimate Addons, Premium Addons, Qi Addons y Royal Addons. Cada uno carga su propio código en todas las páginas, aunque solo se use uno o dos de sus elementos. Por eso la portada pide 140 archivos al abrirse: 78 de estilos y 88 de código.

Una base de datos inflada Medio

Cada vez que se guarda una página, WordPress guarda una copia. Ya hay 885 copias, 323 de ellas de la portada, y la base de datos llega a unos 200 MB cuando una web de este tamaño debería pesar una fracción de eso. Eso hace más lentas las consultas y los respaldos.

WordPress y 23 plugins sin actualizar Seguridad

Hay versiones nuevas pendientes, varias con arreglos de seguridad. En una web que cobra en línea y recibe datos de clientes, esto no debería esperar.

Archivos que se cargan sin necesidad Medio

La tipografía Poppins se descarga en 14 grosores aunque se usan dos o tres. Además se carga completo el paquete de íconos Font Awesome y, para todos los visitantes, los íconos del panel de administración de WordPress.

Lo que vamos a hacer

  • Respaldo completo antes de empezar. Si algo no queda igual, se vuelve atrás en minutos.
  • Caché de página con LiteSpeed y la red de distribución (CDN) de Hostinger, ajustada para que las reservas y el pago siempre muestren datos al día.
  • Dejar uno o dos paquetes de complementos. Revisamos página por página qué elemento usa cada sección; si alguno dependía de un paquete que sale, lo rehacemos igual.
  • Imágenes convertidas a WebP y al tamaño en que se muestran, con carga diferida de las que no se ven al abrir la página.
  • Tipografía e íconos: solo los grosores y los íconos que se usan, servidos desde el mismo hosting.
  • Estilos y código que no hacen falta para la primera pantalla se cargan después.
  • Limpieza de la base de datos y un límite de copias por página para que no se vuelva a inflar.
  • Actualización de WordPress y de los plugins por grupos, probando la reserva y el pago después de cada grupo.
  • Medición antes y después con la misma herramienta, para que vean el resultado en números.
Meta: 85 o más en celular y el contenido principal en menos de 2,5 segundos.
